# Сайт ИВП

Next.js, Postgres через Neon, деплой на Vercel. Оформление перенесено из
репозитория старого сайта `ivp-site`: палитра, шрифты, типографская шкала и
компоненты. Тексты и структура - свои, со старого сайта не переносилось
ничего.

Что осталось за заказчиком - в [OTKRYTYE-VOPROSY.md](./OTKRYTYE-VOPROSY.md).

## Запуск

```
npm install
cp .env.example .env    # заполнить своими значениями
npm run db:migrate
npm run dev
```

Строка подключения к базе в репозиторий не попадает: репозиторий публичный,
`.env*` под `.gitignore` с первого коммита.

## База

Миграции лежат в `db/migrations` и применяются по очереди через
`npm run db:migrate`.

Если из окружения нет сети до Neon, все миграции собраны в один файл
`db/neon-console.sql` - его копируют целиком в SQL Editor консоли Neon.
Файл идемпотентный, повторный запуск ничего не ломает. Пересобирается
командой `node scripts/build-neon-sql.mjs` после любой правки миграций.

## Переменные окружения

| Переменная | Зачем |
| --- | --- |
| `DATABASE_URL` | Подключение к Postgres |
| `NEXT_PUBLIC_SITE_URL` | Адрес сайта, попадает в письма и партнерские ссылки |
| `ADMIN_TOKEN` | Вход в админку: `/admin?token=...` |
| `LEADS_EMAIL` | Почта, на которую уходят заявки |
| `ALLOW_DEV_PAYMENTS` | `1` включает кнопку "считать оплаченным" на боевом стенде |

## Индексация

Закрыта целиком и тремя способами сразу: мета-тег на всех страницах, заголовок
`X-Robots-Tag` и `robots.txt`. Открывать только по отдельной команде заказчика.

## Оплата

Не подключена. Кнопка ведет на страницу "здесь будет оплата", заказ при этом
создается и сохраняется. В режиме разработки там же есть кнопка "считать
оплаченным": без нее не проверить сценарий с партнерской меткой.

Подключение настоящего эквайринга - вторая реализация интерфейса
`PaymentProvider` (`createPayment` / `handleWebhook`), а не переписывание.

## Партнерская механика

Ссылка вида `/atlas?ref=КОД`. Код кладется в cookie на 180 дней и снимается с
адреса. Первый код не перезаписывается: побеждает первая ссылка. При оформлении
заказа код записывается в сам заказ, потому что подтверждение оплаты от
платежной системы приходит без браузера покупателя.

При оплате, если у покупателя еще нет закрепления, оно создается и запирается
навсегда. Начисление: 20 процентов с первой покупки этого покупателя, 10 со
всех последующих. Статус при создании - "ожидает подтверждения", в "к выплате"
переводится вручную из админки.

Закрепление защищено триггером в самой базе: UPDATE и DELETE по запертой строке
отклоняются.

## Демонстрация кабинета педагога

`/demo/kabinet` - это демонстрация идеи, а не продукт. Данные живут только в
`sessionStorage` браузера: между сессиями не сохраняются и на сервер не уходят.

Главное, что она показывает: видимость управляется на уровне отдельного поля, а
не тетради целиком. У полей про деньги, про провалы и про то, с кем педагог не
работает, переключателя нет вовсе - наружу они не выносятся никогда.
